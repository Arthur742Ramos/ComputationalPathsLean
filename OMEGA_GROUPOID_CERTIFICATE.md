# Extensional 3-truncated weak omega-groupoid certificate

This focused artifact formalizes the higher structure carried by the
repository's computational paths.  The selected result is

```text
ComputationalPaths.Path.PalomarOmegaGroupoid.main_result
```

It is checked for every carrier type `A` and packages the following data.

1. A 1-cell is the repository's `Path` record: an equality proof together
   with a list of explicit `Step` metadata.
2. A 2-cell is a Type-valued `Derivation₂` generated by reflexivity, primitive
   rewrite steps, inverses, and vertical composition.
3. `Derivation₂` and `RwEq` are proved equivalent in both directions, with
   both reification round trips checked by the kernel.
4. A 3-cell is a finite `Derivation₃` of named coherence generators.  Parallel
   2-cells are connected by the `rweq_transport` generator because their
   induced equality proofs live in `Prop` and are therefore proof-irrelevant.
5. Unit, associativity, inverse, interchange, pentagon, and triangle
   coherences are exposed as explicit 3-cell witnesses.
6. Parallel 3-cells admit explicit 4-cell fillers, and parallel 4-cells admit
   explicit indexed higher-cell fillers.
7. The certificate records concrete lower-dimensional syntax witnesses: a
   one-step path differs from the empty-trace reflexive path, and a reflexive
   2-cell differs from its explicit composite with a reflexive 2-cell.

The scope is intentionally exact.  This is an extensional Lean construction
whose contraction above dimension two uses the declared proof-irrelevance and
parallel-filler boundaries.  It does not claim that `Path` is an intensional
HoTT identity type, and it does not claim that the broad parent development is
a constructive Squier finite-derivation-type proof.

## Reproduce

The project is pinned to Lean 4.24.0 and Mathlib v4.24.0.  Run:

```bash
lake build
lake build ComputationalPaths.Path.OmegaGroupoid.PalomarStatement
lake env lean Challenge.lean
lake env lean Solution.lean
scripts/check-palomar-omega.sh
```

`Challenge.lean` contains the single statement-side `sorry` required by the
Palomar comparison protocol.  `Solution.lean` and the focused statement module
contain no proof holes or custom axioms.
